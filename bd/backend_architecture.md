# Backend Архитектур ба API удирдамж

Энэхүү баримт бичиг нь төслийн шинэчлэгдсэн Backend архитектурын онцлог болон Frontend/Backend хөгжүүлэгчдэд зориулсан API ашиглах заавар юм.

---

## 1. REST API ба Чиглүүлэлт (Standard RESTful Routes)

Өмнө нь ашиглаж байсан "Single Endpoint" (бүх хүсэлтийг `/app/process` рүү явуулж `pc` header-ээр удирддаг байсан) аргачлалаас татгалзаж, уламжлалт бөгөөд олон улсын стандарт болсон **REST API** архитектур руу бүрэн шилжсэн.

*   Бүх API чиглүүлэлтүүд `routes/api.php` дотор тодорхой заагдсан.
*   `GET`, `POST`, `PUT`, `DELETE` гэх мэт HTTP аргуудыг зориулалтын дагуу ашиглана.
*   **Authentication:** `auth:sanctum` ашиглан хамгаалагдсан тул хүсэлт бүрийн Header-т `Authorization: Bearer <token>` дамжуулах шаардлагатай.

**Frontend-ээс дуудах жишээ (Check-in хийх):**
```javascript
fetch('http://localhost/api/events/1/checkins', {
    method: 'POST',
    headers: {
        'Content-Type': 'application/json',
        'Authorization': 'Bearer <token>' // Заавал байна
    },
    body: JSON.stringify({
        ticket_id: 123,
        device_id: "DEVICE_ABC"
    })
})
```

## 2. Clean Architecture (Services & Jobs)

Backend-ийн код маш цэвэрхэн (Clean) байх ёстой бөгөөд логикууд давхаргуудад дараах байдлаар хуваагдсан:

### 2.1. Controllers (`app/Http/Controllers/`)
Controller нь зөвхөн Request хүлээн авах, Validation хийх, Service рүү дамжуулах, эцэст нь Response буцаах гэсэн үүрэгтэй. Баазтай харьцах логик (DB queries) энд огт бичигдэхгүй.

### 2.2. Services (`app/Services/`)
Бизнесийн гол логикууд (бааз руу хадгалах, засах, Event унагаах гэх мэт) энд бичигдэнэ. 
Жишээ: `CheckinService`, `MessageService`, `NotificationService`.

### 2.3. Queue & Jobs (`app/Jobs/`)
Маш их хэмжээний дата орж ирэх үед (жишээ нь Оффлайн төхөөрөмжүүд датагаа Sync хийх үед) сервер гацахаас сэргийлж **Queue** ашиглана. 
`SyncController` нь орж ирсэн мянга мянган датаг `array_chunk`-аар 100, 100-аар нь хуваагаад `ProcessSyncChunk` гэдэг Job руу шидэж, арын фон дээр (Background) ачаалалгүйгээр ажиллуулдаг.

> [!WARNING]  
> Хөгжүүлэлтийн орчинд Sync API турших үед Terminal дээрээ заавал `php artisan queue:work` командыг ажиллуулж орхих шаардлагатай! Эс бөгөөс датанууд Queue дотор оочерлоод гацаад байна гэсэн үг.

## 3. Validation ба Pagination (Үндсэн функцүүд)

Бид Laravel-ийн уламжлалт FormRequest болон шууд `paginate()` дуудахын оронд Base Controller (`App\Http\Controllers\Controller`)-д бичигдсэн дундын функцүүдийг ашиглана.

*   **Validation (`$this->validateMe()`):**
    Controller дотор `$this->validateMe($request, [...rules...])` гэж дуудна. Хэрвээ алдаа гарвал автоматаар `AxiomException` шидэгдэж, Frontend рүү нэгдсэн стандартаар алдаа буцна.
*   **Pagination (`$this->getGridData()`):**
    Жагсаалт харуулах API дээр ашиглана. Frontend-ээс `filters` (хайлт шүүлт), `orders` (эрэмбэлэлт), `perPage` (хуудсанд хэд харагдах) гэсэн параметрүүдийг явуулахад автоматаар тооцоолж, хуудаслалттай дата буцаана.

## 4. Оффлайн ажиллагаа (Offline-First Architecture)

Арга хэмжээний үеэр интернэт тасарсан ч гэсэн тасалбар шалгалт хэвийн үргэлжлэх ёстой.

1.  **Pre-sync (Урьдчилж татах):**
    Арга хэмжээ эхлэхээс өмнө интернэттэй үед шалгагч төхөөрөмжүүд нь `GET /api/events/{id}/download-data` API-г дуудаж, тухайн арга хэмжээний бүх тасалбар болон хэрэглэгчдийн мэдээллийг өөрийн гар утасны **Local Database (SQLite, WatermelonDB гэх мэт)**-д бүрэн татаж хадгална.
2.  **Оффлайн баталгаажуулалт:**
    Интернэтгүй үед утас өөр дээрээ байгаа локал баазаасаа хайлт хийж тасалбарыг баталгаажуулна. Хэрэглэгчдийн хоорондын харилцаа болон төхөөрөмжүүд хоорондын мэдээлэл солилцоог дотоод сүлжээгээр буюу **Bluetooth Mesh / WiFi Direct (P2P)** технологиор шийднэ.
3.  **Post-sync (Нөхөж илгээх):**
    Интернэттэй болох үед локал баазад хуримтлагдсан үйлдлүүдийн жагсаалтаа `POST /api/sync` API руу бөөнөөр нь шидэж үндсэн сервертэйгээ өгөгдлөө нэгтгэнэ.

## 5. Алдаа боловсруулалт (Exception Handling)

Алдаа гарсан тохиолдолд систем нь хувьсах алдааны код бус `AxiomException` ашиглан нэгдсэн форматаар хариу буцаана. 

Бид `findOrFail()` гэх мэт хүрээний (framework) шууд алдаа шиддэг функцээс татгалзаж, баазаас шүүхдээ `where('id', ...)->first()` ашиглаж шалгаад, олдохгүй бол гараараа `AxiomException` шиддэг болгосон. Ингэснээр Frontend үргэлж хүлээгдэж буй форматтай алдаа хүлээж авна.

**Алдааны форматын жишээ:**
```json
{
    "response_code": "error",
    "response": "Event not found"
}
```

## 6. WebSockets (Real-time дата)

Төсөл нь реал-тайм мэдэгдэл болон өгөгдөл солилцоход **Pusher** протоколыг ашигладаг. Локал хөгжүүлэлтийн орчинд үүнийг орлуулахын тулд **Soketi** (Node.js дээр суурилсан) серверийг ашиглана.

*   **Асаах команд:** Terminal дээр `npx @soketi/soketi start`
*   **Холбогдох порт:** `6001`

Frontend хөгжүүлэгчид нь `pusher-js` болон `laravel-echo` санг ашиглаж, өгөгдсөн порт болон түлхүүрээр холбогдож реал-тайм өгөгдлийг (Check-in хийгдсэн, шинэ мессеж ирсэн гэх мэт) хүлээж авна.
